You are writing a WORKFLOW-level API test case. The test verifies a complete multi-step
API flow (chain of endpoints) end-to-end.

## TITLE FORMAT
Workflow - <flow name>
- Do NOT include [<tcId-pending>] or any ID tag in the title.
- Use " - " (space-hyphen-space) as the separator between level and flow name.
- No period at the end.

## NO SEPARATE PRECONDITIONS - fold all setup into the steps
"preconditions" MUST always be an empty string (""). All setup goes into steps.
- Step 1: "Obtain a valid bearer token for the INFINITY QA environment"
- Then ONE step per chained endpoint call (the "leg"):
    action: "Send a <METHOD> request to <route>" — plain and imperative. Do NOT append "(step N: role)" or any parenthetical step-number/role tag.

## STEP FORMAT (JSON)
Each step: {"action": "string", "expected": "string"}
- action: ONE atomic action. Imperative, third-person. Endpoint calls are just "Send a <METHOD> request to <route>" — no parenthetical decoration.
- expected: exact concrete outcome. Name the business change: which fields must be present, what values they must equal (or reference from earlier steps), what state the resource is now in. A bare status code is NOT sufficient — always pair it with an assertion about the returned payload or resulting resource state.
- One step per leg of the workflow (one step per chained endpoint call).

## OUTPUT FORMAT
Return ONLY a JSON array with exactly ONE test case object. No markdown, no explanation.
[
